# U-076a accessibility audit (WCAG 2.2 AA), round 1

Diff: origin/main..d5e9eeffe7d13d55d979d58c2539d250dedbcfbf (ramble, read-only)
Scope: src/components/RichTextEditor/, src/components/EditorialAdmin/, src/app/(ops)/ops/editorial/, plus the shared Field, Button, DataTable and ActionNotice they rely on.

VERDICT: FAIL (1 blocking)

## Blocking
1. RichTextEditor.tsx, Cancel in the link panel (setLinkHref(null)): the panel unmounts while focus is on the Cancel button, so focus drops to body. Keyboard users lose their place (WCAG 2.4.3 Focus Order). Fix: return focus to the Link toolbar button (or the editor) after Cancel. Remove and Apply already move focus via editor.chain().focus().

## Advisory
2. RichTextEditor.tsx, Link button: opening the panel does not move focus to the "Link address" input, so a keyboard user gets no cue where the field is. Focus the input on open.
3. RichTextEditor.tsx, contenteditable (role="textbox", aria-multiline, aria-labelledby): name and role are correct, but aria-invalid is not set when errorText is present; only aria-describedby is. Add aria-invalid when errorText is set.
4. RichTextEditor.tsx, toolbar: role="toolbar" promises arrow-key navigation (ARIA APG), but every button is a separate Tab stop and no arrow handling exists. Either implement roving tabindex or drop the role and keep a labelled group of plain buttons.
5. RichTextEditor.tsx, Link button uses aria-pressed for both "link active" and "panel open". Mixed meaning; consider aria-expanded for the panel.
6. Link-panel validation error (linkProblem) and Field error text have no role="alert" or live region, so a failed Apply is not announced.
7. Server-side save notices (ActionNotice wraps Alert) and field errors after redirect: focus is not moved to the notice or the first invalid field. Confirm Alert carries a live role (not inspected in this round) and that post-navigation focus lands on the h1.
8. Editor keyboard exit: no trap found. Tab leaves the editor (Tiptap does not capture Tab outside lists). Inside lists Tab sinks list items and Shift+Tab lifts them, and it still exits at top level. Escape is not handled; acceptable because nothing is modal. Pass with note.
9. Loading state role="status" exists only during SSR and is replaced on hydration, so it is rarely announced. No action beyond awareness.
10. Heading levels: the editor allows h2 to h4 in content, while the toolbar offers h2 and h3 only. Content can produce h4 without h3 (skipped level). Advisory unless content is restricted to h2/h3.
11. Button.module.css :focus-visible uses outline: 2px solid transparent plus a box-shadow ring; the ring disappears in forced-colors mode. Add a forced-colors fallback.
