### Non-blocking
- Accessibility gap (results after the footer in the DOM): NOT blocking. Measured with JS off: tab order is skip link, header, then 11 footer links (Gift guide through Privacy), then Filters, the day form, the chip groups, and the result links last. The skip link lands on `#main`, which holds only the h1 and lede, so a screen reader hears an empty `main`, then the footer, then unlabelled content after it. That is a real defect for a JS-off keyboard or screen-reader user, and by the letter it is WCAG 2.4.3 Focus Order and 1.3.2 Meaningful Sequence (both A). It does not block because: (1) WCAG 2.2 conformance is judged against the technologies the page relies on, and this site relies on JavaScript, so a JS-off fallback is outside the AA claim in the design doc (NFR, PRD-69); the JS-on page, the one that claim covers, is unchanged; (2) it is not a regression: before this diff JS-off users got a skeleton forever, after it they get working filters and results in a worse reading order; (3) the order cannot be fixed in this architecture, because Next appends streamed sections at the end of `body`, so the only complete fix is not streaming for JS-off. If the owner decides the JS-off page is inside the AA claim, flip this to blocking. Cheap mitigation to log with the audit item: a `<noscript><a href="#browse-results">Skip to results</a></noscript>` inside `main` on `page.tsx`, with that id on the streamed wrapper (a target that is visible once the rule applies). Log as an audit item; the e2e test pins visual order only, so it will not notice if the DOM order is ever fixed.
- `src/styles/base.css` rule is safe with JavaScript on. Both rules sit inside `@media (scripting: none)`, which is false whenever scripts run (I read `matchMedia('(scripting: none)')`: false with JS on, true with JS off). `scripting: initial-only` (print) is not `none`. With JS on, the unmatched `div[hidden]` is removed by React's own script as before. Browser support (Chrome 120, Firefox 113, Safari 17; `:has` earlier) only means older browsers keep today's behavior.
