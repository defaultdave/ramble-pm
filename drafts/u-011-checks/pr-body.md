## U-011 Catalog schema and read layer

Issue: https://github.com/defaultdave/ramble/issues/16 (critical tier, targets `integration`)

This is the pattern-setter for the catalog, booking and host units. It adds the catalog tables, the Zod schemas, and nine server-only read functions. Nothing imports the reads yet except the tests.

### What was built

**Tables** (`src/server/db/schema/catalog.ts`, `schema/policies.ts`, with `relations()`)

- `hosts`: `slug`, `name`, `description`, `time_zone` (IANA, for the sessions unit), `created_at`.
- `categories`, `neighborhoods`: `slug` (unique, kebab-case), `name`.
- `experiences`: host, category, neighborhood and cancellation tier FKs (all `NOT NULL`, all `ON DELETE RESTRICT`); `slug` (kebab, not unique); `name`; nullable content columns `description`, `meeting_point`, `included`, `duration_minutes`, `accessibility_notes`; `status`; `outdoor`, `weather_policy`, `weather_decision_hours`; `age_rule`, `min_age`, `max_age`; `tax_treatment` (default `unknown`); `waiver_required`, `waiver_document_id` (uuid, no FK); `link_out_url`, `affiliate_url`; `created_at`.
- `price_options`: `experience_id`, `kind`, `price_minor` (integer cents, USD, no currency column), `uses_space` (default true).
- `slug_history`: `entity_kind`, `entity_id` (no FK, it points at one of four tables), `slug`, `retired_at`; unique on kind and slug for categories and neighborhoods (a partial index), unique on kind, entity and slug for experiences and hosts.
- `cancellation_tiers`: `key` (unique), `name`, `full_refund_hours_before`, `is_default`.

**Enums** (each `pgEnum` is built from the tuple in `src/lib/catalog.ts` that the Zod enum uses): `experience_status` (`draft`, `in_review`, `live`, `paused`, `guide_only`), `age_rule`, `weather_policy` (`rain_or_shine`, `decided_before_start`), `tax_treatment`, `price_kind` (`adult`, `child`), `slug_entity_kind` (`category`, `neighborhood`, `experience`, `host`).

**CHECKs and indexes**

- `price_options_price_not_negative`; unique `(experience_id, kind)`.
- `experiences_age_rule_limits`: `all_ages` and `twenty_one_plus` take no limits, `minimum_age` takes a minimum and no maximum, `age_range` takes both with `min_age <= max_age`.
- `experiences_outdoor_has_weather_policy`; `experiences_weather_decision_hours` (the hours are set exactly when the policy is `decided_before_start`, and are positive).
- `experiences_guide_only_has_link`; `experiences_link_out_url_http` and `experiences_affiliate_url_http` (see review round 1).
- Slug kebab CHECK on hosts, categories, neighborhoods and experiences; `experiences_duration_positive`; `cancellation_tiers_hours_not_negative`; a partial unique index so at most one tier is the default.
- Indexes on the three experience FKs.

**Triggers and reference rows** (custom migration `0002`, hand-written SQL)

- `retire_slug()` writes a changed slug to `slug_history` for all four kinds. Category and neighborhood: runs on insert and update, and any category (neighborhood) that takes a retired slug deletes its row. Experience and host: runs on update, and a row is deleted only when the same entity takes its own old slug back.
- Three `cancellation_tiers` rows: `flexible` (24 hours, default), `moderate` (48), `strict` (168).

**Migrations**: `0001_catalog_tables.sql` (generated by `pnpm db:generate`) and `0002_slug_history_and_cancellation_tiers.sql` (`drizzle-kit generate --custom`).

**Zod** (`src/lib/catalog.ts`): `GuestExperienceSchema`, `HostExperienceSchema`, `PriceOptionSchema`, `CategorySchema`, `NeighborhoodSchema`, `CancellationTierSchema`, `RetiredSlugSchema`, plus the enum tuples and `z.infer` types `GuestExperience`, `HostExperience`, `PriceOption`, `Category`, `Neighborhood`, `CancellationTier`, `RetiredSlug`. The rules that tie fields together (age limits, outdoor weather policy, guide-only link) are checked in Zod as well, from one function.

### How each pattern-note rule is met

- **Where things live.** Tables in `schema/catalog.ts` and `schema/policies.ts`; reads in `db/catalog.ts` and `db/policies.ts`, exporting reads only; Zod, tuples and types in `src/lib/catalog.ts` (Q2). Types are `GuestExperience`, `PriceOption` and so on, never `*Row` or `*Dto` (B5).
- **Columns.** As listed above. Guests see `live` and `guide_only` (Q3) through one private `guestVisible` condition that all guest reads use, built from the same `guestVisibleStatuses` tuple as the guest schema's status enum. If a hidden row ever slipped past the SQL, the Zod parse would throw. No soft delete; every FK is `on delete restrict`.
- **Slugs.** Kebab-case, unique for categories and neighborhoods. Experience and host addresses carry the uuid and lookup is by ID (Q4). The history table covers all four kinds and a trigger writes it (Q5). `findRetiredSlug` reads it; the 301s stay with the redirects unit.
- **Money.** `price_minor integer CHECK (>= 0)`, `kind` and `uses_space` per option, and the child-space flag on price options only (Q8).
- **Age, weather, tax, waiver.** As in the note, with `rain_or_shine` and `decided_before_start` plus `weather_decision_hours` (Q7); `tax_treatment` defaults to `unknown`; `waiver_document_id` has no FK.
- **Cancellation tiers.** `key`, `name`, `full_refund_hours_before`, `is_default`, with the 24 hour, 48 hour and 7 day rows inserted by migration (Q6).
- **Guest reads take no `Caller` (Q1, B6).** None reads cookies, headers, `getCaller()` or the clock, so a `'use cache'` wrapper can hold them (B14). They take only plain arguments.
- **Restricted reads.** `caller` comes first and each read checks one role, `Role.HostOwner`, with no hierarchy and no `try`/`catch`. `listHostExperiences` calls `requireRole(caller, Role.HostOwner, { hostId })` before any query. `getHostExperience` reads the row by ID, calls `requireRole` with the row's `hostId`, then returns. Ownership is never in a `WHERE` clause in place of `requireRole`.
- **Arguments are Zod-parsed first.** A guest read given a non-uuid ID returns `null` and lists return `[]`. A failed check throws `ForbiddenError`. There is no `catch` anywhere (B13).
- **Results are `Schema.parse(row)`.** Never Drizzle rows. Zod's strip drops `taxTreatment`, `waiverDocumentId`, `createdAt` and the host's `timeZone` and `createdAt` from guest results.
- **`dbRead`, one statement per call.** The experience reads fetch the host, tier and price options with a relational `with`, so there is no query in a loop.
- **Caching seam.** Nothing imports `next/cache` or any cache module. Guest reads are uncached and argument-only, and every guest experience carries `id`, `hostId`, `categoryId` and `neighborhoodId` for tagging.
- **Tests (ADR 0006).** `src/lib/catalog.test.ts` and `tests/db/catalog.db.test.ts`, covering the note's minimum list; see below.
- **Out of scope respected.** No sessions, photos, legal documents, settings, redirects, pricing, filters, tags, writes, host suspension, authorization matrix, or seed data (other than the tier rows).

### Decisions for Dave

1. **Content columns beyond the named list.** The note names status, weather, age, accessibility, tax, tier and waiver. PRD-9 also needs a description, meeting point, what is included and a duration, so `experiences` has `description`, `meeting_point`, `included` and `duration_minutes`, plus `accessibility_notes`. All are nullable so a draft can save before it is complete. `hosts` has `slug`, `name`, `description` and `time_zone`. Say if any should be left to the editor units.
2. **One price option per kind per experience.** I added a unique index on `(experience_id, kind)`, reading "per-person prices by type (adult, child)" as one price each. If hosts may offer, say, two adult prices, drop the index in this unit.
3. **What a guest result holds.** `GuestExperience` omits `taxTreatment`, `waiverDocumentId` and `createdAt`, and embeds `host` (id, slug, name, description), `cancellationTier` and `priceOptions`. Category and neighborhood come by id and are matched to `listCategories()` and `listNeighborhoods()`. The checkout units can add a narrower read for the tax treatment and waiver document.
4. **`getHostExperience` order of checks.** The note says to select the row's `host_id`, check it, then return, and also says one statement per call. I read the whole row in one statement and check before returning, which satisfies both. A well-formed ID that matches no row returns `null` before any role check, so an unauthorised caller can tell "missing" from "forbidden" for a uuid. The IDs are random uuids, so I did not add a probe-proof path. Say if you want one. Accepted for this read, but by-ID reads over guessable ids must not copy it.
5. **Malformed IDs on restricted reads.** A malformed host ID lists `[]` and a malformed experience ID returns `null`, before the role check, matching the guest rule. No data is returned either way.
6. **Slug trigger beyond "on slug updates".** For categories and neighborhoods the trigger also runs on insert and removes a retired row when its slug is live again, so a 301 can never point at the address it came from. Experience and host history follows the PM's clarification (see review round 1).
7. **Extra CHECKs.** Link and affiliate URLs must be http(s) with a real host (a `javascript:` URL in an `href` is the risk), the duration and weather deadline must be positive, names must not be blank, and slugs must be kebab-case on all four tables.
8. **Tier keys and names.** `flexible`, `moderate`, `strict`, named the same. The terms text ("full refund up to 24 hours before") is built from `full_refund_hours_before`, which is the pricing unit's job.
9. **Harness change.** `tests/db/harness.ts` rewrites `"public".` in a temp copy of the migrations (described above). It is the smallest change I found that keeps one schema per test file.
