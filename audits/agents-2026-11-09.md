## Tonight's experiments

### A1110-1 (type C, tooling): the profiler counts each model call once

- **Finding:** `tools/session-profile.py` counted one call per transcript record that carries `usage`. Claude Code writes one record per content block of a reply (text, each tool use), all with the same message id and the same usage, so calls read high and the 20-call floor let in sessions with as few as 10 real calls. Tonight it printed `calls=38` for 83936be7, where `token-audit` and `day-cost.py` both say 20; reconciling the two took two extra calls. On the baseline day it printed 1,280 calls for e2e-money 9be20418 where the real count is 586; the baseline's "1,280 calls" for that lane came from this count.
- **Change:** `tools/session-profile.py`, docstring lines 9 and 10, `profile_session` lines 53 and 77 to 78, `profile_subagents` lines 112 and 123 to 125: count a call once per message id (per transcript and message id for subagents). 9 lines added, 5 removed, 1 file. `--now` reads only the latest call and is unchanged.
- **Metric and target:** main-session calls equal `token-audit`'s count per session; the summed main-session calls on the baseline day within 5% of `day-cost.py`'s `interactive` calls (the gap is sessions under the 20-call floor); exit 0, no error line; peaks and starting contexts unchanged.
