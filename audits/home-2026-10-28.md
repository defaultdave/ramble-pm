## Findings from the pass

Ran 2026-10-29 on `main` at `48a1f6d`: six lenses, each finding checked by an independent verifier. Findings only.

### Summary

- 65 verified findings: architecture 14, DRY 17, caching 9, accessibility 3, visual 17, performance 5. By urgency: 1 now, 14 before-launch, 49 later and 1 fine. They merge into 50 items (H-19 to H-68), and 19 of those need an owner call. The verifiers refuted another 15.
- The three that matter most: H-19, the hero search row breaks from 768 to about 1100 px. H-20, home modules that are switched off still render because of SQL operator precedence. H-21, dark mode never declares `color-scheme`, so the date icon is 1.25:1 and fails WCAG 1.4.11.
- No new blocking architecture violation (the B17 duplicates predate this pass). No WCAG 2.2 AA failure in the shell or in the states that could be rendered. Nobody has audited the loaded live page in a browser yet (H-23).
- Answer to H-1: lab LCP does not tell the variants apart (they land within 30 to 120 ms of each other). The LCP element is the hero h1. The Suspense swap reveals it about 300 ms after first paint, and four render-blocking stylesheets sit in front of that. On the server, a cold base request waits about 4 database round trips plus 0.2 s for the h1. Variant b stays flat at about 0.16 s, and variant a only helps when the cache is warm.
- H-1 decision: first try H-34 (blocking CSS, h1 outside Suspense). Then measure the Neon round trip from a Vercel function (H-22). If p95 is under about 150 ms, keep base. Above that, take b under the H-39 conditions, never a.

**Reading of the numbers**

1. At 300 ms per query or less, the lab cannot separate the variants. React's `$RC` swap reveals the h1 about 300 ms after the last paint, and the CSS chain gates that paint. So the data wait hides behind it (H-34).
2. The data wait starts to matter at a database round trip of roughly 300 ms, because the cold h1 needs about 4 round trips. H-22 measures the real number.
3. If H-22 comes in under about 150 ms p95, keep base. Above that, take b once H-39 is settled.
4. Do not take a: it brings no cold gain, adds a layout-shift path, and delays the week by one more round trip when cold.
5. H-36 (widen the minute key) is a cheaper lever on the warm-state wait, but it is a product call and has not been measured.

### Refuted

- **"A cover upload invalidates nothing" (architecture).** Nothing calls `addPhoto` yet (`TODO(U-074b)`), the design puts invalidation in the caller, and the existing listing change already publishes the experience tag. So it is not a live defect. The caching lens's version is kept as H-24, the reminder for U-074b.
- **"The category rail and the hero's neighborhood list have no display cap" (architecture).** They are small curated lists, already capped at 100 when read. Capping the select would break searching by neighborhood, and the rail scrolls inside its own box.
- **"The cover read waits for the content read, a second waterfall" (architecture).** The cover IDs include the "On this week" cards, so the cover read has to wait for the week read either way. The fix that applies is H-37.
- **"The same settings read fails open in the banner and closed on the home page" (architecture).** A notice failing open and a page that acts on a switch failing closed is the H-4 rule, applied the same way on the experience page.
- **"H-7 confirmed: the session-day window is written twice" (architecture).** Home defines its window once (`thisWeekWindow`), and a db test already pins both edges.
- **"H-3 confirmed: the card price reads every price option" (architecture).** Fixed on main by 5121048 (PR 220), with tests.
- **"Every guest route answers no-store, so the in-memory cache is the only cache" (caching).** That header is what `next start` sends for any partial-prerender route. On Vercel the shell is still served from the CDN, and home data stays per-request because of HomeContent's own `connection()`.
- **"The card focus ring depends on `:has()`" (a11y).** Every browser in PRD-67 supports `:has()`.
- **"320 px reflow passes; the rails scroll sideways" (a11y).** This is the intended design and passes WCAG 1.4.10, so there is nothing to fix.
- **"The Storybook axe harness needs its own rule set" (a11y).** The repo already runs addon-a11y in CI and turns off the duplicate-landmark rules per story.
- **"Confirms H-3: the Kids' wheel class card reads 'From $0 per person'" (visual).** Fixed on main by 5121048. It only needs a visual recheck.
- **"Simulated LCP is 2.7 to 2.8 s, above PRD-68" (performance).** ADR 0006 already chose the profile. The figure comes from the simulation counting scripts that finished downloading within 31 ms on localhost; DevTools-throttled LCP is 1.45 s.
- **"Client JS: 196 KB over the wire, INP unmeasured" (performance).** TBT is 5 to 34 ms against a 200 ms budget. ADR 0006 uses TBT as the lab stand-in for INP on purpose.
- **"Image LCP cannot be judged; no home photo asks to be preloaded" (performance).** On phones the first card photo is below the fold, so lazy loading is right. The remaining measurement gap is already H-17.
- **"Cache headers, compression and the RSC payload are partly recovered" (performance).** Every check that was measured passed, and the repo overrides no cache policy. What remains is an optional check on the preview deployment.
