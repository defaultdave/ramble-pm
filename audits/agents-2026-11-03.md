## Tonight's experiments

### A1104-1 (type C, tooling): the rounds tool reads posted check runs

- **Finding:** since 2026-11-02 no verdict files are written under `drafts/`; the agents post verdicts only as GitHub check runs (`scripts/merge-desk/post-check.ts`). `tools/check-rounds.py 2026-11-03` printed "No verdict files written" on a day when 24 PRs were checked, so Step 1's rounds table needed manual `gh` calls.
- **Change:** `tools/check-rounds.py`, +45 / -9 (54 changed lines, over the 40-line guideline because it adds a second data source in one function). `posted_rounds()` makes one `gh pr list` and one GraphQL call (check suites of the agents App only) for PRs updated since the day began, takes check runs completed in the day's window, and counts a new round only after a round with a FAIL (a re-check on a merge of main stays in its round). If `gh` fails, it prints one line and the file-based output is unchanged.
- **Metric and target:** rounds for every unit checked in the day in one call, no more steps than the file-only version.
- **Test:** 2026-11-03: one call, 2.7 s, 2,261 characters, 24 PRs (by hand tonight: 6 calls, about 12K characters, 3 PRs). Baseline day 2026-10-29: the file-based lines are identical to the old tool's (43 unit folders, 21 needing round 2, same round 1 failures), plus 46 PRs. 2026-11-01: file lines identical, plus 20 PRs including PR 299's posted FAIL round. With `gh` absent from PATH: one "not read" line, file output intact.
- **Result: passed.** Published with the night's commit. Revert: `git revert` that commit's `tools/check-rounds.py` hunk.
